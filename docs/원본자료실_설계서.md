# 원본 자료실 설계서

> **이 문서는 "원본 자료실" 기능 작업의 기준 문서입니다.**
> 이 기능을 작업할 때는 항상 이 문서를 먼저 읽고, 문서와 다르게 구현해야 할 이유가 생기면 구현 전에 먼저 질문하고 문서를 갱신합니다.

## 목표

- 로그인한 사용자가 관리자가 만든 3단계 분류(대그룹 → 중그룹 → 소그룹)를 탐색해 원본(PDF, 이미지) 열람
- 제품 자료, 교육과정 자료 등 어떤 종류의 자료든 담을 수 있는 범용 자료실
- 다운로드/인쇄 불가, 파일 주소 노출·복사 불가 (캡처·화면녹화 수준 우회는 허용)
- 사용자별로 열람 가능한 분류·자료를 다르게 지정
- 챗봇(RAG)과는 별개 기능. 기존 RAG 구조는 건드리지 않음

## 저장 구조

- 원본 파일: Cloudflare R2 비공개 버킷 (Supabase Storage 사용 안 함)
- R2 비밀키는 Vercel 환경변수에만 존재. 프론트 코드에 절대 포함 금지
  (R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET)
- Supabase 테이블:
  - library_categories: id, name, parent_id(상위 분류, 대그룹은 null), level(1~3),
    sort_order, visibility('inherit'|'all'|'restricted'), 설명(선택)
  - library_docs: id, title, category_id(어느 단계 분류에든 연결 가능), r2_key,
    file_type('pdf'|'image'), version, is_latest, previous_doc_id,
    visibility('inherit'|'all'|'restricted'), 업로더, 등록일
  - user_groups / group_members: 권한 그룹과 소속 사용자
  - library_permissions: 대상(분류 또는 자료) + 허용 대상(그룹 또는 개인 사용자)
  - library_view_logs: 사용자, 자료, 열람일시

## 권한 규칙

- visibility='inherit'(기본값)이면 가장 가까운 상위 분류의 설정을 따름
- 대그룹이 inherit이면 전체 공개로 간주
- 'all'은 로그인 사용자 전체, 'restricted'는 library_permissions에 지정된 그룹 소속자 또는 개인만
- 관리자는 전체 열람
- 권한 없는 분류·자료는 목록에도 표시되지 않음 (Supabase RLS로 서버에서 차단)
- 열람 URL 발급 함수에서도 권한 재확인 (자료 ID를 알아내 요청해도 거부)

## 열람

- 화면: 대그룹 카드 → 중그룹 목록 → 소그룹 목록 → 자료 목록 → 뷰어
  (각 단계에서 하위 분류와 해당 단계에 직접 연결된 자료를 함께 표시)
- 상단에 현재 위치 표시 (예: 교육과정 > 신입 입문 > 1주차), 클릭 시 해당 단계로 이동
- 자료 제목 검색 (권한 있는 자료만 검색됨)
- /api/library-url 함수: 로그인·권한 확인 후 R2 임시 열람 URL 발급 (만료 60초) + 열람 로그 기록
- 뷰어는 URL을 받자마자 파일을 메모리로 불러와 렌더링하고, URL을 화면·링크·새 탭 어디에도 노출하지 않음
- PDF: PDF.js(cdnjs) 캔버스 렌더링 / 이미지: 메모리에서 불러와 표시
- 페이지 이동, 확대/축소(모바일 핀치 포함)
- 다운로드/인쇄 버튼 없음, 우클릭·드래그·Ctrl+S·Ctrl+P 차단
- 모바일 우선 (현장 인력이 폰으로 사용)

## 관리자 기능

- 분류 관리: 대/중/소그룹 추가·이름 수정·순서 변경·삭제 (최대 3단계)
  - 하위 분류나 자료가 있는 분류는 삭제 전 경고, 비어 있을 때만 삭제 가능
- 자료 업로드: 파일 선택 + 제목 + 분류 위치 + 공개범위 입력
  → /api/library-upload-url 함수가 관리자 확인 후 R2 임시 업로드 URL 발급
  → 브라우저에서 R2로 직접 업로드 (Vercel 함수 용량 제한 때문)
- 자료 이동(다른 분류로), 제목 수정
- "새 버전으로 교체": 새 파일 업로드 시 기존본은 is_latest=false (사용자에게 숨김, 관리자만 열람)
- 자료 삭제 시 R2 파일도 함께 삭제
- 권한 관리: 그룹 생성, 그룹에 사용자 배정, 분류 또는 자료별 허용 그룹/개인 지정
- 자료별 열람 기록 조회

## 구현 전 결정 사항

> 위 설계서를 현재 코드 구조(2026-10 기준)와 대조해 정한 내용입니다. 아래 내용이 위 본문과 다르면 **아래가 우선**합니다.

### 현재 구조에서 확인된 전제

- 로그인은 서버 확인 없이 브라우저가 `users` 테이블 전체를 받아 직접 비교하는 방식이다. 로그인 증명(토큰)이 없고 모든 테이블이 `anon` 키로 읽기·쓰기가 열려 있다. (`users.pw`는 평문)
- 그래서 본문의 "서버(RLS, 함수)에서 권한 차단"은 로그인 증명이 있어야 성립한다.
- 서버 코드(`api/`, `package.json`)가 전혀 없고, 챗봇은 브라우저에서 Supabase·Gemini를 직접 호출한다.
- 기존 `groups`(id, name), `group_members`(group_id, user_id), `group_products`(group_id, product_id)가 있다. 챗봇의 제품군 제한에 쓰이고 있으며(설치법인 31명, 스토어 85명, 지국 24명), 어느 그룹에도 속하지 않으면 챗봇 제품군이 보이지 않는다.

### 결정 1. 로그인 방식: 서버 함수가 토큰을 발급 (방식 a)

- 자료실 전용 로그인 확인 함수가 아이디·비밀번호를 서버에서 확인하고, 만료 시간이 있는 서명된 토큰을 발급한다.
- `/api/library-*` 함수는 이 토큰을 검증해서 사용자와 관리자 여부를 판단한다. 화면에서 보내는 "나는 admin" 같은 값은 믿지 않는다.
- 권한 판정은 RLS가 아니라 함수가 서비스 키로 DB를 읽어서 한다. 자료실 테이블은 `anon` 키로 접근할 수 없게 막는다(RLS로 anon 차단).
- 기존 챗봇, 회원 관리, 로그인 화면은 지금 방식 그대로 두고 건드리지 않는다. 필요해지면 나중에 Supabase 로그인으로 옮긴다.
- 이에 따라 본문의 "Supabase RLS로 서버에서 차단"은 "자료실 테이블을 anon에서 막고, 함수가 권한을 판정해 내려주는 방식"으로 읽는다.

### 결정 2. 그룹: 기존 그룹 + 자료실 전용 그룹 병행 (방식 ③)

- **기존 그룹**(`groups` / `group_members`)은 자료실 권한 대상으로도 쓸 수 있다. 이미 배정된 회원을 다시 배정하지 않는다. 기존 그룹 테이블은 자료실 때문에 변경하지 않는다.
- **자료실 전용 그룹**은 새 테이블로 만든다. 기존 `group_members`와 이름이 겹치므로 본문의 `user_groups / group_members`는 `library_groups / library_group_members`로 읽는다. 챗봇 제품군 권한에는 영향이 없다.
- `library_permissions`의 허용 대상은 기존 그룹, 자료실 전용 그룹, 개인 사용자 세 종류다. 사용자는 기존 그룹 또는 전용 그룹 중 하나라도 허용되어 있으면 열람할 수 있다(합집합).

### 구현에 반영할 사항

- **서버 함수 3개 이상**: 본문의 `/api/library-url`, `/api/library-upload-url` 외에, R2 파일 삭제와 토큰 발급(자료실 로그인)이 필요하다. R2 비밀키는 서버에만 있으므로 삭제도 함수가 한다.
- **Vercel 환경변수 추가**: 본문의 R2 항목 외에 Supabase 서비스 키(서버 전용)와 토큰 서명용 비밀값이 필요하다. 모두 프론트 코드에 넣지 않는다.
- **R2 버킷 CORS**: 브라우저에서 R2로 직접 업로드·열람하므로 허용 사이트 설정이 필요하다.
- **모바일 뷰어**: 화면 확대를 막아 둔 설정(`maximum-scale=1.0`) 때문에 핀치 확대는 뷰어에서 직접 구현한다. 아이폰 메모리 한도 때문에 PDF는 페이지별로 그리고 크기 상한을 둔다.
- **하단 메뉴**: 사용자 화면 하단 메뉴가 4개라 "자료실"이 들어가면 5개가 된다. 사용자 화면 4곳의 메뉴를 모두 고쳐야 한다.

### 결정 3. 비밀번호 저장 방식: 이번 작업에서는 하지 않음 (별도 작업으로 진행)

- 자료실은 현재 저장 방식(평문) 그대로 두고 만든다. 자료실 로그인 확인 함수가 DB의 비밀번호와 서버에서 직접 비교해 토큰을 발급하므로, 암호화 없이도 자료실의 권한 확인은 성립한다.
- 비밀번호 암호화 저장은 자료실과 별개의 보안 작업으로, 자료실 완료 직후 별도로 진행한다. (챗봇 로그인, 회원 등록, 비밀번호 변경, CSV 일괄 등록, 기존 회원 일괄 변환이 함께 바뀌는 큰 작업이므로 분리한다.)
- 이 작업이 끝나기 전까지 `users` 테이블이 모든 브라우저로 내려가는 문제는 남아 있다는 점을 인지하고 진행한다.

### 결정 4. 회원 아이디 변경: 연결된 기록이 따라오도록 DB 설정 추가

- 현재 `inquiries`, `user_chat_logs`, `group_members`는 `users.id`를 가리키며 삭제 시 연쇄 삭제만 있고, 아이디 변경 시 연쇄 갱신(`ON UPDATE CASCADE`)이 없어 기록이 있는 회원의 아이디 변경이 실패한다.
- 위 3개 외래키에 `ON UPDATE CASCADE`를 추가한다.
- 자료실에서 새로 만드는 테이블(`library_view_logs`, `library_group_members`, `library_permissions` 등)의 사용자 참조도 처음부터 `ON UPDATE CASCADE`로 만든다.
- 운영 DB 변경이므로 **적용 전에 사용자에게 한 번 더 확인**을 받는다.

### 결정 5. 자료실 로그인: 자동

- 사용자가 평소처럼 로그인하면, 그 시점에 브라우저가 서버 함수로 아이디·비밀번호를 보내 자료실용 토큰을 받아 둔다. 자료실 진입 시 비밀번호를 다시 묻지 않는다.
- 토큰은 화면 메모리에만 둔다(새로고침하면 로그인이 풀리는 현재 동작과 동일). 로그아웃하면 토큰도 버린다.

### 결정 6. 무료 사용량 에너지바 (admin 계정에만 표시)

- 관리자 대시보드에 "무료 사용량" 카드를 두고, 남은 용량을 에너지바로 보여 준다. 막대가 가득 차 있을수록 여유가 많다는 뜻이며, 남은 비율이 50% 이하면 노랑, 20% 이하면 빨강으로 바뀐다. **`admin` 계정에만 보이고 다른 관리자와 일반 사용자에게는 보이지 않는다.**
- 표시 항목은 세 가지다.
  1. **AI 질문(오늘)**: 오늘 성공한 질문 수 / 무료 일 한도(Flash-Lite 1,000건, Flash 250건). 질문 기록(`chat_logs`) 기준의 추정치다.
  2. **데이터 저장공간**: Supabase 데이터베이스 사용량 / 무료 500MB. DB가 알려 주는 크기를 읽는 조회 함수(`get_db_usage`)가 필요하다.
  3. **자료실 파일 저장공간 (자료실 구현 시 추가)**: Cloudflare R2 사용량 / 무료 10GB.
     - `library_docs`에 파일 크기(`file_size`, 바이트) 컬럼을 두고 업로드 시 기록한다. 사용량은 이 값의 합계로 계산하며(최신본뿐 아니라 보관 중인 이전 버전 포함), Cloudflare에 따로 묻지 않는다.
     - 자료 업로드 화면과 자료실 관리 화면에도 같은 에너지바를 보여 줘서, 용량이 부족할 때 업로드 전에 알 수 있게 한다.
