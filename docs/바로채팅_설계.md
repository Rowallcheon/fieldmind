# 바로 채팅 (그룹 설정) 설계

## 무엇인가
관리자 > 그룹 권한 관리에서 그룹에 **💬 바로 채팅**을 체크하면, 그 그룹 사용자는 로그인했을 때 제품군·모델 선택 줄 없이 **채팅창만** 보인다. 허용된 제품군(그 사용자가 속한 모든 그룹의 허용 제품군 합집합)의 문서 전체에서 찾아 답한다.
- 여러 그룹에 속해 있으면 **하나라도 체크된 경우 바로 채팅**.
- 바로 채팅 사용자에게는 기존 "제품군/모델 직접 선택" 줄을 보여 주지 않는다(숨김).
- 눈 아이콘으로 끈 문서(`enabled=false`)는 검색 대상에서 제외한다.

## 데이터
`groups.direct_chat boolean not null default false` — `docs/sql/group_direct_chat_01.sql` (운영 DB 변경: 적용 전 사용자 확인). 칸이 없어도(SQL 적용 전) 일반 그룹 생성·수정은 동작하도록 체크했을 때/바뀐 때만 값을 보낸다.

## 답변 방식 (index.html, `directRoute` / `runAnswer`)
1. 허용 문서 전체가 `DIRECT_ALL_LIMIT`(8만 자) 이하 → 선택 단계 없이 전부 AI에게 전달.
2. 그보다 많으면 **선택 단계**: `번호 | 제품군 > 모델 | 분류 | 제목` 목록만 AI에게 주고 JSON(`select`/`ask`/`unknown`)을 받는다(문서 본문은 보내지 않음). 목록은 코드가 등록된 데이터로 자동 생성한다.
   - `select`: 문서 최대 `DIRECT_PICK_MAX`(10)건, 본문 합계 `DIRECT_CTX_MAX`(30만 자) 이내로 **답변 단계**에 전달.
   - `ask_model`: 에러코드·사양·부품·점검/교체 방법·사용설명서·유로도처럼 **모델마다 내용이 다른 질문인데 모델을 말하지 않았으면** 답하지 않고 먼저 "어느 제품·모델인가요?"를 묻고 제품군 → 모델 버튼을 보여 준다(모델명을 직접 입력해도 됨). 고르면 그 모델 문서로 원래 질문에 답한다. 이미 모델을 말했거나 고른 뒤에는 묻지 않는다. 문서가 적어 선택 단계를 건너뛰는 경우에는 답변 지침(규칙 8)이 같은 일을 한다.
   - `ask`: 질문이 모호하면 되묻기(+ 눌러 고르는 보기 버튼). 대화 기록에 남겨 다음 답을 이어서 해석.
   - `unknown`/해석 실패: **제품군 → 모델 선택**을 자동으로 보여 주고, 고르면 그 모델 문서 전체로 같은 질문에 다시 답한다.
3. 답변 단계에서 AI가 "해당 정보를 찾을 수 없습니다"로 답하고 참조 문서가 없으면 → 같은 제품군/모델 선택으로 안내.
4. 못 찾은 질문은 관리자 로그(`chat_logs`)에 실패(`is_ok=false`)로 남는다. 로그의 제품군은 `전체 검색`, 모델은 실제로 쓴 모델명.

## 시험
`node tests/direct-chat/e2e.js` (가짜 DB/Gemini). 실제 Gemini의 문서 고르기 정확도는 운영에서 확인한다.

## 선택 카드 (되묻기 화면)
- 제품군/모델/보기 선택은 번호가 붙은 **선택 카드**로 보여 준다(`directChips`). 모델은 개수 제한 없이 **전부** 나오고, 10개를 넘으면 검색창이 생기며 목록은 카드 안에서 스크롤된다. 고르면 선택 표시와 함께 카드가 잠긴다. 입력창에 직접 입력해도 된다.
- 사용자가 제품군(예: 정수기)을 이미 말했으면(`ask_model`의 `product`) 제품군 단계를 건너뛰고 그 제품군의 모델 전체를 바로 보여 준다.
